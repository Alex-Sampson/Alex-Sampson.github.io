<section>
  <p>
    A personal website for a graduate student has two competing requirements. It
    should look like something you'd want to send to a colleague — typographically
    settled, easy to read, calm. And it should be easy enough to update that
    adding a paper or a new course doesn't become a chore you put off. The first
    requirement pushes you toward hand-tuning HTML. The second pushes you toward
    a CMS. <code>Jekyll</code> is a compromise that I think gets the balance about right.
  </p>
  <p>
    The pitch is short. Each page is a Markdown file. Each post is a Markdown file
    in <code>_posts/</code>. Templates live in <code>_layouts/</code> and are
    written in HTML. Lists (projects, courses, talks) can live as YAML in
        <code>_data/</code>code> and be rendered by a Liquid <code>for...endfor</code>code> loop.
    GitHub Pages builds the site automatically when I push, so deployment is just
    <code>git push</code>. There is no database, no admin panel, and no server to
    keep alive.
  </p>
</section>

<section>
  <h3 class="section-label">What I gave up by not writing raw HTML</h3>
  <p
    Less than I expected. The pages I would otherwise hand-write are still
    available — anything I want to lay out by hand sits in HTML, and Jekyll happily
    passes it through. What I gained is a structural separation between content
        <code>_data/</p>code> and be rendered by a Liquid <code>for...endfor</code>code> loop.
    whole site without having to touch the text. That is the same lever as a CMS,
    minus the moving parts.
  </p>
</section>

<section>
  <h3 class="section-label">What I gave up by not using a heavier framework</h3>
  <p>
    A few things I haven't missed. There is no interactive search out of the box,
    no built-in commenting (which is fine — I would not turn it on anyway), and
    plugins are constrained on GitHub Pages. For an academic page where the work
    is the work, I haven't found this limiting.
  </p>
</section>

<section>
  <h3 class="section-label">The hybrid</h3>
  <p>
    The compromise I've landed on is to keep the things that change often as
    Markdown or YAML (posts, talks, projects), and the things that change rarely
    as HTML templates (the homepage, the CV, the post layout). Updates take
    minutes. Redesigns take longer but only happen when I want them to. That is
    the right shape for a graduate-student page.
  </p>
</section>
